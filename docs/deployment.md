# Развёртывание и эксплуатация

Приложение обслуживает страницу, файлы Godot и четыре небольших API: конфигурация, генерация, необязательный план и решение. Данные матча остаются во вкладке. Перезапуск контейнера не требует миграций и восстановления базы.

## Публичный адрес

Запустите образ на платформе с поддержкой Docker, портом 8080 и HTTPS. Health check: `GET /healthz`. Он отвечает 200, если Web-экспорт присутствует. На VPS перед контейнером можно поставить Caddy или другой обратный прокси:

```caddyfile
race.example.com {
    reverse_proxy race:8080
}
```

Это пример для Caddy и Race в одной Docker-сети; замените домен своим и направьте DNS на сервер. TLS завершает прокси. Сохраняйте исходный Host. Не включайте запись тел запросов и заголовка Authorization в прокси или внешнем APM. Стандартный сервер Race работает без access log.

Сертификаты HTTPS может хранить прокси. Race не нуждается в томах для пользовательских данных. В `compose.yaml` файловая система приложения доступна только для чтения, процесс работает без root и Linux capabilities.

## Настройки

| Переменная | Значение по умолчанию | Для чего |
|---|---|---|
| `JEV_MODEL` | `jev-1.13.0` | Версия модели в официальном API |
| `JEV_TIMEOUT_SECONDS` | `3` | Ограничение ожидания провайдера |
| `JEV_INPUT_USD_PER_MILLION` | `0.042` | Оценка стоимости входных токенов |
| `RACE_RULES_FILE` | — | TOML с правилами генератора |
| `RACE_PLUGIN` | — | Функция регистрации дополнительных агентов |
| `RACE_WEB_DIR` | `web/game` | Путь к Web-экспорту |

В настройках нет общего `TYPESAFE_API_KEY`: посетитель вводит свой токен. Контейнер не читает ключи из старого проекта, файлов пользователя или окружения машины.

Обычный запрос Jev не повторяется автоматически: скрытые повторения могли бы увеличивать расходы. HTTP 401/403 останавливает гонку с предложением ввести другой токен. Тайм-ауты и лимиты API отмечаются в отчёте; технически неполный матч не объявляет победителя.

## Загрузка на медленном интернете

WebAssembly, игровой пакет и JavaScript заранее сжимаются Brotli и gzip при сборке Docker. Сервер выбирает поддерживаемый браузером вариант и отдаёт готовый файл с правильным MIME-типом. В текущей сборке 39,89 МиБ превращаются в 8,39 МиБ с Brotli или 11,47 МиБ с gzip. Повторный заезд использует обычный кеш общих ресурсов. Service worker не используется.

Для локальной сборки установите `pip install Brotli==1.1.0`, если нужен тот же размер загрузки; без него сборщик создаёт gzip. Фоновая иллюстрация формы дополнительно оптимизирована: около 106 КиБ.

Главный объём — WebAssembly Godot. Сжатие фона на несколько килобайт не заменяет сжатие движка. Ресурсы исходного демо, не используемые гонкой, исключены; изображения остаются WebP. При замене ресурсов сравнивайте результат визуально, особенно края спрайтов и прозрачность.

## Приватность и границы демонстрации

Токен приходит в заголовке Authorization, существует в памяти обработчика на время запроса и передаётся TypeSafe. Он не попадает в URL, конфигурацию игрового iframe, отчёт или ответы API. Обработка ошибок не возвращает посетителю тело ответа провайдера. Cookies и серверные сессии не создаются.

На сервере нет API сохранения/чтения матчей и нет каталога отчётов. Кнопки скачивания создают файл в браузере через Blob. При закрытии вкладки, перезагрузке и новой игре состояние очищается. Приложение не управляет браузерными расширениями, дампами операционной системы и политиками хранения у самого TypeSafe.

Итог проверяется игровым клиентом, поэтому отчёт не является защищённым спортивным результатом. Для рейтинга с призами потребуется отдельная серверная симуляция. В текущем варианте лимит параллельных запросов защищает сервер от бесконечного ожидания; для большой публичной аудитории дополнительно задайте ограничения трафика на прокси.
