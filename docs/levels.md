# Как устроены уровни

Уровень — обычный словарь: seed, список препятствий, финиш и правила. `generate()` не обращается к моделям и ничего не записывает. Одинаковые seed, количество препятствий и настройки дают одинаковую трассу.

```python
from race.levels import generate, GeneratorConfig

track = generate(seed=42, count=20)
print(track["events"][0])

relaxed = GeneratorConfig(spacing=576, max_obstacles=60)
long_track = generate(seed=17, count=50, config=relaxed)
```

Сервер предоставляет тот же генератор через `POST /api/track`:

```bash
curl http://localhost:8080/api/track \
  -H 'Content-Type: application/json' \
  -d '{"seed":42,"count":20}'
```

## Баланс и геометрия

По умолчанию доступны 4–40 препятствий. Генератор перемешивает набор из шести типов, затем берёт следующий набор. В полном наборе каждый тип встречается один раз. На границе наборов одинаковые препятствия не стоят подряд. В последнем неполном наборе часть типов отсутствует — это ожидаемо.

Координаты привязаны к сетке 64 пикселя. Разрыв занимает ровно две клетки, то есть 128 пикселей. Базовая скорость — 300 пикселей/с, сила прыжка — 725, гравитация — 2100. Без столкновений один прыжок покрывает примерно 207 пикселей. Контроллер модели запускает приём за 120 пикселей до центра препятствия.

Разрыв проверяется после его дальнего края. Неудачный проход возвращает робота на землю со штрафом, поэтому он не может бесконечно падать. Между центрами соседних препятствий минимум 448 пикселей: остаётся время приземлиться, получить следующее решение и восстановить управление.

`GeneratorConfig` проверяет ограничения. Скорость нельзя увеличить одной настройкой: сначала нужно пересчитать прыжки, интервалы и момент исполнения в Godot. Количество препятствий меняет длину гонки; разнообразие и цена ошибки определяются правилами.

Если включён дрон, в наборе должно быть не менее трёх типов: его безопасный проход требует заряда. Это ограничение сохраняет возможность пройти длинную трассу без штрафов при экономном выборе действий.

## Настройка запущенного сервера

Пример — [examples/rules.toml](../examples/rules.toml):

```bash
RACE_RULES_FILE=examples/rules.toml python -m race
```

Для Docker добавьте `RACE_RULES_FILE=/app/examples/rules.toml` в `environment` сервиса. Этот файл входит в образ. Свой файл можно добавить при сборке или подключить отдельным томом только для чтения.

| Параметр | По умолчанию | Смысл |
|---|---:|---|
| `start_x` | 704 | Первое препятствие, кратно 64 |
| `spacing` | 448 | Интервал; кратен 64 и не меньше 448 |
| `finish_margin` | 384 | Участок до финиша после последнего препятствия |
| `max_obstacles` | 40 | Верхняя граница формы, допускается до 100 |
| `penalty_seconds` | 2 | Прибавка к итоговому времени |
| `hazard_types` | Все шесть | Не менее двух различных типов |

## Добавление нового препятствия

1. Добавьте описание в `HAZARDS` в `race/levels.py`: идентификатор, русское имя, описание ситуации для модели, безопасное действие и допустимую альтернативу.
2. Нарисуйте объект в `_draw_hazard()` в `game/track_renderer.gd`.
3. Если ему нужна особая физика, добавьте проверку в `_resolve()` в `game/race.gd`.
4. Проверьте прохождение каждого заявленного безопасного действия и то, что после ошибки робот продолжает гонку.
5. Пересоберите Web-версию. Если меняется набор действий, обновите `ACTION_TEXT`, управление и адаптеры моделей.

Модель не получает поля `best` и `alternative`. Они нужны игровому контроллеру для проверки исхода. В её контекст попадают описание препятствия, заряд и законные варианты действий. Версия формата уровня находится в поле `version`; при несовместимых изменениях увеличьте её.
