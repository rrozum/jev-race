# Проверка изменений

```bash
pip install -e '.[dev]'
pytest
docker build -t jev-race:local .
docker run --rm -p 8080:8080 --read-only --tmpfs /tmp jev-race:local
```

Автоматические проверки используют подставной адаптер без платных запросов. Они проверяют воспроизводимость и геометрию трасс, ограничения слоёв, форму запросов к Jev, обработку ошибок, отсутствие серверной истории и утечек токена. Сборка Docker дополнительно проверяет GDScript и наличие ресурсов.

Перед выпуском пройдите браузерный сценарий:

1. Введите личный токен, выберите 4 препятствия и подготовьте трассу. Подождите несколько секунд: робот и музыка не должны стартовать.
2. Нажмите любую клавишу. Проверьте W/S/Q/пробел, кнопки 1–4 и левый клик.
3. Переключите обе камеры. Пройдите разрыв удачно и ошибитесь на нём: гонка должна продолжиться в обоих случаях.
4. Дождитесь финиша. Движение и музыка останавливаются. Скачайте HTML и JSON; HTML должен открываться без интернета.
5. Начните новую игру и обновите страницу. Отчёт и токен должны отсутствовать. В браузере не должно появляться cookies, localStorage или sessionStorage с пользовательскими данными.
6. Повторите с неверным токеном и отключённой сетью. Интерфейс должен объяснить ошибку, не объявляя технический сбой проигрышем модели.
7. Откройте страницу на узком экране и с ограничением скорости сети. Проверьте доступность формы и сжатую передачу `.wasm`/`.pck`.

Для браузерной автоматизации можно использовать `tests/browser_smoke.py` с установленным Playwright. Скрипт запускает временный сервер с тестовым агентом, проходит полный матч, проверяет готовность/отчёт/очистку и сохраняет снимки в игнорируемый каталог `artifacts/`.

```bash
pip install playwright
playwright install chromium
python tests/browser_smoke.py
```

Фактически выполненные проверки первого выпуска описаны в [validation.md](validation.md).
